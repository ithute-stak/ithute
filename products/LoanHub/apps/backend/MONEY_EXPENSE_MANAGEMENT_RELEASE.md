# LoanHub Branch Money and Expense Management Release

## Release purpose

This release adds an enterprise branch treasury and expense-management module to LoanHub. It tracks every verified money-in and money-out movement by company, branch, date, payment method, purpose, supporting proof, staff member and source transaction.

The recognised payment methods are identifiers and evidence channels. They are not live provider integrations in this release:

- Bank
- Swipped
- goLink
- CDAS
- M-Pesa Wallet
- M-Pesa Merchant
- M-Pesa Agent
- EcoCash Wallet
- EcoCash Agent
- EcoCash Merchant
- Cash

For non-cash channels, LoanHub records a proof/reference number or proof-document location and the verifying staff member. It does not claim that it initiated or confirmed a provider transaction automatically.

## Main company route

`/company/expense-management`

The page contains:

1. **Overview** — consolidated opening balance, owner contributions, money in, money out, expected closing balance, branch reporting status and payment-channel totals.
2. **Daily money book** — every branch entry, payment evidence, loan disbursement, repayment, expense and adjustment for the selected business date.
3. **Branch funding** — headquarters issues morning funds to another branch and LoanHub creates matched headquarters money-out and destination-branch money-in entries.
4. **Expense setup** — company-defined expense categories. No business categories are seeded automatically.
5. **Statements** — date-range, branch, direction and multi-channel filtering, printing and CSV export.
6. **Settings** — headquarters branch, timezone, currency, 16:30 auto-submission, proof policy and controlled reopening.

## Headquarters and opening balance

One active branch can be labelled **Headquarters**. Company owners and administrators may change this designation from the branch-management page or treasury settings.

The consolidated opening figure is displayed as:

`total opening balance = all branches' previous closing balances + today's owner contributions`

The consolidated closing calculation is:

`closing balance = previous closing balances + all money in - all money out`

Owner contributions are included once in money in. The separate opening display makes the source of new operating capital visible without double-counting it in closing.

## Daily branch workflow

1. Headquarters issues morning funds to a branch where required.
2. The branch records collections, verified payment proofs, loan disbursements and operating expenses throughout the day.
3. Loan disbursements, repayments, assisted-account fees, subscriptions, marketplace unlocks and platform-claim settlements automatically create treasury entries when completed through their normal LoanHub workflows.
4. Manual entries may be recorded for genuine money movements not already generated by another module.
5. At the configured cutoff, default `16:30 Africa/Maseru`, open branch days are submitted automatically.
6. Each submission stores an immutable snapshot of opening, channel totals, expense totals, money in, money out, closing balance and variance.
7. Headquarters or authorised management can review branch submissions. Reopening preserves the original submission and creates a later sequence when resubmitted.

The backend scheduler checks due branch days every 60 seconds by default while the FastAPI service is running:

- `TREASURY_AUTO_SUBMIT_ENABLED=true`
- `TREASURY_AUTO_SUBMIT_INTERVAL_SECONDS=60`

The company-specific cutoff and timezone are configured in the UI.

## Selected-channel calculation

The overview provides a checkbox for every recognised payment method. LoanHub immediately calculates only the selected channels:

- selected money in
- selected money out
- selected net movement
- matching entry count

The same multi-channel filter is available for statements and CSV export.

## Money-out classifications

- Loan disbursement
- Operating expense
- Branch remittance sent
- Platform/company charge
- Refund
- Authorised adjustment out
- Other money out

Every operating expense requires a company-defined expense category and description.

## Payment evidence rules

Cash creates a physical cash-transaction record. Non-cash channels create a verified manual payment record and require supporting evidence when the company proof policy is enabled.

Stored evidence includes:

- LoanHub payment reference
- payment-method identifier
- external proof/reference number
- proof-document URL or storage location
- verification notes
- verifying user and verification time
- branch, date, amount, direction and purpose

No wallet PIN, bank password, OTP or card security code should ever be captured.

## Roles

### Company Owner / Company Administrator

- configure headquarters and treasury policy
- view all company branches
- create expense categories
- record owner contributions
- issue branch funding
- submit, reopen and review branch days
- view and export all statements

### Branch Manager

- view the authorised branch
- record branch entries and expenses
- submit the branch day
- receive headquarters funding
- view branch statements

### Finance Officer

- record verified money movements
- issue and receive branch funding where permitted
- process disbursements, repayments and charge settlements
- print receipts and reconcile statements

### Collections Officer

- receive and allocate loan repayments
- record permitted collection entries
- view the assigned branch money book

### Auditor / Compliance / Risk roles

- read transparent payment evidence, submissions and statements according to existing tenant-role permissions

## Initial setup

1. Open **Company → Branches** and mark one active branch as Headquarters.
2. Open **Company → Money & expenses → Settings**.
3. Confirm currency, `Africa/Maseru`, `16:30`, proof requirements and reopen policy.
4. Create only the expense categories genuinely used by the company.
5. Test a small headquarters-to-branch funding transfer.
6. Record one money-in and one expense entry.
7. Submit a branch day and verify the immutable submission snapshot.
8. Generate a date-range statement and compare it with the payment register and accounting journal.
